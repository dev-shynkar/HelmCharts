{{- if not .Values.auth.existingSecret }}

WARNING: no RPC authentication. The linuxserver.io image only enables it when
USER and PASS are set, so right now anyone who can reach port {{ .Values.service.port }} can add
torrents and browse your filesystem through the web UI.
{{- if .Values.ingress.enabled }}
The Ingress is ENABLED, so this is very likely exposed beyond your cluster.
{{- end }}

  kubectl create secret generic transmission-auth -n {{ .Release.Namespace }} \
    --from-literal=USER=admin --from-literal=PASS='<pick one>'

  # then: auth.existingSecret=transmission-auth
{{- else }}

   Credentials come from the Secret "{{ .Values.auth.existingSecret }}" (keys
   {{ .Values.auth.keys.username }} / {{ .Values.auth.keys.password }}).

   Changing a value there does NOT restart the pod: USER and PASS are read once
   at startup. The chart cannot checksum a Secret it does not own without
   `lookup`, which breaks `helm template`, so after rotating either key:

     kubectl --namespace {{ .Release.Namespace }} rollout restart deploy/{{ include "transmission.fullname" . }}
{{- end }}

{{- if .Values.peerPort.enabled }}

{{ $n = add1 $n }}{{ $n }}. BitTorrent peer port: {{ .Values.peerPort.port }} (TCP and UDP).
{{- if .Values.peerPort.hostPort }}

   It is bound directly on the node (hostPort). Two things are still on you:

     a) Forward {{ .Values.peerPort.port }}/tcp AND {{ .Values.peerPort.port }}/udp on your router to that node's LAN
        address. UDP carries DHT and µTP — forwarding only TCP leaves you
        half-connected.
     b) Confirm it from outside once running: the web UI shows a "Port is
        open / closed" indicator under Preferences -> Network.

   Because of the hostPort the pod can only be scheduled where {{ .Values.peerPort.port }} is free.
{{- else }}

   peerPort.hostPort is off, so nothing outside the cluster can reach it and
   incoming peer connections will not work. Seeding will be effectively dead
   and download speeds much lower than they should be.
{{- end }}
{{- else }}

{{ $n = add1 $n }}{{ $n }}. WARNING: peerPort.enabled is false. Transmission can only make outgoing
   connections — seeding will not work and downloads will be slow.
{{- end }}

{{- if and .Values.persistence.downloads.enabled (eq .Values.persistence.downloads.type "hostPath") }}

{{ $n = add1 $n }}{{ $n }}. Downloads use hostPath {{ .Values.persistence.downloads.hostPath }} of type {{ .Values.persistence.downloads.hostPathType | default "Directory" }}
   on the node selected by your nodeSelector/affinity.
{{- if eq (.Values.persistence.downloads.hostPathType | default "Directory") "Directory" }}

   The pod will not start at all if that path is missing, which is deliberate:
   an empty /downloads makes every torrent look lost.
{{- else }}

   hostPathType is not Directory, so Kubernetes creates the path as root:root
   0755 when missing — and UID {{ $env.PUID | default "1000" }} cannot write to it. Worse, an empty
   /downloads makes every torrent look lost. Consider hostPathType: Directory.
{{- end }}

   Either way, confirm ownership once after the first start:

     sudo chown -R {{ $env.PUID | default "1000" }}:{{ $env.PGID | default "1000" }} {{ .Values.persistence.downloads.hostPath }}
{{- end }}
