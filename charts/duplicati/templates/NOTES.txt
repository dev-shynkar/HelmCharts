{{- if not .Values.auth.existingSecret }}

{{ $n = add1 $n }}{{ $n }}. WARNING: no credentials configured.

   * The UI has no password yet. Duplicati prints a one-time sign-in link in the
     pod log — find it with:

       kubectl --namespace {{ .Release.Namespace }} logs deploy/{{ include "duplicati.fullname" . }} | grep -i signin

   * The server database is NOT encrypted, so every backend credential you enter
     is stored in the clear on the config volume.

   Fix both:

     kubectl create secret generic duplicati-secret -n {{ .Release.Namespace }} \
       --from-literal=DUPLICATI__WEBSERVICE_PASSWORD='<ui password>' \
       --from-literal=SETTINGS_ENCRYPTION_KEY="$(openssl rand -base64 32)"

     # then: auth.existingSecret=duplicati-secret

   Keep SETTINGS_ENCRYPTION_KEY somewhere safe and OUTSIDE these backups —
   without it the server database cannot be read again.
{{- else }}

{{ $n = add1 $n }}{{ $n }}. Credentials come from the Secret "{{ .Values.auth.existingSecret }}".
   Required keys:
{{- if .Values.auth.keys.password }}
     {{ .Values.auth.keys.password }}
{{- end }}
{{- if .Values.auth.keys.encryptionKey }}
     {{ .Values.auth.keys.encryptionKey }}
{{- else }}

   NOTE: auth.keys.encryptionKey is blank, so the server database is stored
   unencrypted along with every backend credential in it.
{{- end }}

   Changing a value in that Secret does NOT restart the pod: the variables are
   read once at startup. The chart cannot checksum a Secret it does not own
   without `lookup`, which breaks `helm template`, so after rotating either key:

     kubectl --namespace {{ .Release.Namespace }} rollout restart deploy/{{ include "duplicati.fullname" . }}
{{- end }}

{{- if not .Values.persistence.config.enabled }}

{{ $n = add1 $n }}{{ $n }}. WARNING: persistence.config is disabled.

   /data holds the server database: your backup definitions, schedules and
   encryption passphrases. It is currently in the container filesystem and is
   lost on every restart — the backup files themselves survive, but restoring
   from them means rebuilding the configuration and remembering the passphrase
   by hand. Enable it:

     persistence:
       config:
         enabled: true
         size: 1Gi
{{- end }}

{{- if and .Values.persistence.source.enabled (eq .Values.persistence.source.type "hostPath") }}

{{ $n = add1 $n }}{{ $n }}. /source is a hostPath ({{ .Values.persistence.source.hostPath }}) of type {{ .Values.persistence.source.hostPathType | default "Directory" }}
   on the node your nodeSelector picked, mounted {{ if .Values.persistence.source.readOnly }}read-only{{ else }}READ-WRITE — consider persistence.source.readOnly: true{{ end }}.

   Verify it actually contains your data before trusting the first backup:

     kubectl --namespace {{ .Release.Namespace }} exec deploy/{{ include "duplicati.fullname" . }} -- ls -la /source

   An empty directory here means Duplicati will record an empty backup as a
   successful version, and retention will start pruning the good ones.
{{- if ne (.Values.persistence.source.hostPathType | default "Directory") "Directory" }}

   hostPathType is not Directory, so the kubelet creates that directory when it
   is missing instead of refusing to start the pod. That is the exact failure
   above. Consider persistence.source.hostPathType: Directory.
{{- end }}
{{- end }}
